# Как работать над проектом с телефона

Инструкция для владельца проекта. Компьютер и терминал не требуются.

---

## Что нужно на телефоне

| Инструмент | Зачем |
|---|---|
| Браузер с включённой «Версией для ПК» | Создание и правка файлов на github.com |
| Приложение GitHub Mobile | Просмотр статуса проверок и уведомлений |
| Приложение-аутентификатор | Коды двухфакторной защиты |
| Заметки | Хранение recovery-кодов и списка сервисов |

Включить «Версию для ПК»:
- Chrome: три точки справа вверху → «Версия для ПК»
- Safari: значок «аА» слева в адресной строке → «Полная версия сайта»

---

## Создание нового файла

1. Открыть репозиторий citadel
2. Нажать Add file → Create new file
3. В верхнее поле вставить полный путь файла, например:
   src/lib/config/site.ts
   Папки создадутся автоматически.
4. В большое поле вставить содержимое
5. Прокрутить вниз → Commit changes → Commit changes

Отдельно создавать папки не нужно.

---

## Изменение существующего файла

1. Открыть файл в репозитории
2. Нажать значок карандаша справа вверху
3. Выделить весь старый текст и удалить
4. Вставить новое содержимое целиком
5. Commit changes → Commit changes

Правило проекта: файлы всегда заменяются целиком, никогда по кусочкам.

---

## Загрузка изображений

1. Перейти в нужную папку, например design/logos/
2. Нажать Add file → Upload files
3. Нажать choose your files → выбрать изображение из галереи
4. Commit changes

---

## Как понять, что всё в порядке

После каждого сохранения GitHub автоматически проверяет проект.

| Значок рядом с коммитом | Значение |
|---|---|
| Жёлтый кружок | Проверка идёт, подождать 1–2 минуты |
| Зелёная галочка | Всё в порядке |
| Красный крестик | Есть ошибка |

Если появился красный крестик:
1. Нажать на него
2. Нажать Details
3. Найти строки, выделенные красным
4. Скопировать текст ошибки и прислать разработчику
5. Получить исправленный файл целиком

Самостоятельно ничего не удалять и не чинить.

---

## Как посмотреть сайт

После подключения хостинга сайт обновляется автоматически
через 1–2 минуты после сохранения файла. Достаточно открыть
свой домен в браузере телефона и обновить страницу.

---

## Чего нельзя делать

- Не публиковать содержимое файлов с паролями и ключами
- Не переводить репозиторий из Private в Public
- Не удалять файл .gitignore
- Не вставлять адреса криптокошельков в код — только через админ-панель
- Не удалять recovery-коды GitHub и аутентификатора

---

## Если что-то сломалось

GitHub хранит всю историю изменений. Любое действие можно отменить.

1. Открыть файл
2. Нажать History
3. Выбрать версию, которая работала
4. Три точки → View file → скопировать содержимое
5. Вернуться к файлу и вставить старое содержимое

Либо сообщить разработчику, что произошло.
